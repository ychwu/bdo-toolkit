Application integration

Asyncio without capture-thread plumbing

AsyncLiveCaptureSession and AsyncCalibrationSession give async applications awaitable lifecycle control while preserving the existing, tested capture and calibration behavior.

Async application
await / async for
→
Existing session
capture · decode · finalize
Additive by design. The wrappers do not create a second decoder or event queue. Filtering, bounded buffering, TCP reassembly, deposit-origin classification, calibration scoring, and errors remain owned by the synchronous sessions.

Choose the wrapper by outcome

You needUseMain result
A continuous live event streamAsyncLiveCaptureSessionasync for yields BDOEvent
An interactive post-patch calibrationAsyncCalibrationSessionawait stop() returns CalibrationResult

Use the synchronous APIs for ordinary scripts. These wrappers are intended for applications that already run an asyncio event loop, such as async services, bots, and websocket apps.

Live event stream

bdo_toolkit.AsyncLiveCaptureSession

AsyncLiveCaptureSession(*, opcode_profile=None, live_options=None, event_filter=None, origin_observer=None)

The async counterpart to LiveCaptureSession. It is single-use and supports one event consumer. The constructor accepts the same profile, LiveCaptureOptions, EventFilter, and origin-observer arguments.

Smallest complete example

import asyncio
from bdo_toolkit import AsyncLiveCaptureSession

async def main():
    async with AsyncLiveCaptureSession() as session:
        async for event in session:
            print(event.format_human())

asyncio.run(main())
[14:08:31.204] ITEM_RECEIVED source='Gathering' item_id=7003 quantity=4

async with awaits startup and guarantees shutdown when the block exits, raises, or is cancelled. async for awaits each next event without freezing the event loop.

Separate Start and Stop controls

session = AsyncLiveCaptureSession()
consumer_task = None

async def consume_events():
    async for event in session:
        await send_to_app(event)

async def on_start():
    global consumer_task
    await session.start()
    consumer_task = asyncio.create_task(consume_events())

async def on_stop():
    await session.stop()
    await consumer_task

await session.stop() stops packet intake and finalizes pending decoder/origin state. Awaiting the consumer afterward drains events produced by that finalization and surfaces any retained capture error. Create a new session for the next Start action.

Interactive calibration

bdo_toolkit.AsyncCalibrationSession

AsyncCalibrationSession(*, item_id, quantity=None, action="auto", capture_options=None, context_frames=5, min_confidence=0.80)

The async counterpart to CalibrationSession. Capture runs while the user performs the known transfer; await stop() then ends capture, finishes reassembly, scores the frames, and returns the result off the event-loop thread.

import asyncio

from bdo_toolkit import AsyncCalibrationSession

async def main():
    async with AsyncCalibrationSession(item_id=7003, quantity=3) as session:
        await asyncio.to_thread(
            input,
            "Move 3 Potatoes to storage and back, then press Enter...",
        )
        result = await session.stop()
    print(result.summary())

asyncio.run(main())

If the async context exits before stop() is called, it invokes abort(). This matches the synchronous context manager: unfinished calibration is discarded rather than producing a result accidentally.

The first terminal action wins. If stop() began first, a later abort() waits for it and preserves its result. If abort() began first, a later stop() raises RuntimeError.

Cancellation and shutdown

The wrappers retain and shield their underlying worker operations so cancellation cannot abandon a capture or leave a hidden consumer waiting for the next event.

SituationBehavior
Live task cancelled during startupStartup settles; if capture opened, it is stopped before CancelledError escapes.
Pending live poll() cancelledThe single-consumer session is stopped, the pending poll is woken, then cancellation is re-raised.
External live stop()Finalizes normally; the event consumer can drain queued and shutdown-tail events.
Calibration stop() cancelledAnalysis is allowed to settle safely; any completed result is retained in session.result, then cancellation is re-raised.
Calibration context exits unfinishedCapture is aborted and discarded without analysis.
Timeout live polling with its own argument. Prefer await session.poll(timeout=1.0). Cancelling a pending poll—including through asyncio.wait_for()—is intentionally terminal and stops that live session.

Errors, threads, and efficiency

Startup, decoder, observer, and lifecycle exceptions keep their original types. Live iteration preserves the synchronous ordering guarantee: buffered/finalized events are delivered before a retained background failure is raised.

The live wrapper uses one parked worker for a quiet blocking poll and reserves a second worker for shutdown. It does not busy-spin or submit five polling jobs per second, and it remains able to stop even if the host application configured a one-thread default executor. Calibration uses a worker only while starting, stopping/analyzing, or aborting.

No third-party async dependency is added: the wrappers use Python's standard asyncio support and delegate all domain work to the existing sessions.

The calibration wrapper preserves the current synchronous calibration error surface. It does not invent live background-error metadata that CalibrationSession does not currently expose.
